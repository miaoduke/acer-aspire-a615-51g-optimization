## 二、推荐实施方案（分四批）

### 第一批：低难度高价值（1-2 天工作量）
1. **G1 限流原因显示**——高级页新增"限流状态"区：
   - 读 `IA32_THERM_STATUS`（MSR 0x19C）bit0-1 热降频、bit11 电流墙
   - 读 `/sys/class/powercap/intel-rapl:0/constraint_*` 判断 PL 限制中
   - MSR 读取用 `/dev/cpu/0/msr`（root，msr-tools 已装）——只读安全
   - 显示为徽章列表：🟢正常 / 🔴热降频 / 🟡功耗墙 / 🔵电流墙
2. **H1 温度告警通知**——thermal-guard 触发时发桌面通知（GLib.Notification），另加独立高温提醒（80°C 提醒，85°C 限流）
3. **B2 剩余时间估算**——电池页卡片：放电率 60s 滚动平均 → 剩余 Wh ÷ 平均 W
4. **B4 充满预计时间**——充电电流滚动平均 → (满充-当前)÷电流

### 第二批：中等难度（3-5 天）
5. **G3 性能日志**——collector 每 30s 追加 TSV（时间/频率/温度/功耗/限流位），数据目录按天滚动保留 7 天；电池页或新页加"回看"曲线
6. **B1 放电率历史曲线**——同上数据源，电池页加曲线
7. **G2 配置文件轮换按钮**——场景页加"⇄ 轮换"按钮（ac-perf→ac-bal→ac-quiet→bat-save…循环），配全局快捷键
8. **H2 历史回看图表**——复用 Curve 类，加载 TSV 数据画 24h 曲线

### 第三批：较大工程（可选，1 周+）
9. **R1 按应用功耗视图**——cgroup 遍历 + per-cgroup CPU time 差分 → 估算每 App 功耗占比（RAPL 总量按比例分摊）；新增"耗电排行"页
10. **P1 负载自适应建议**——collector 检测持续高负载 + 当前在 bat 场景 → 通知栏建议"切换到性能场景"

### 不做（有依据）
- **G4 BD PROCHOT 写入**——MSR 写入 + 本机死机史，风险>收益（只读显示已含在 G1）
- **R2 页面重构**——现有四页布局已合理，重构成本高收益低
- **P2 进程优先级**——超出电源管理工具定位
- **主题系统**（btop 式）——单用户工具，YAGNI

## 三、技术要点

### 3.1 限流原因读取（G1）核心代码路径
```bash
# 热降频/电流墙（需要 msr-tools，已装）
sudo rdmsr -p 0 0x19C   # IA32_THERM_STATUS: bit0=THERMAL STATUS(热降频中), bit11=RSU(current limit)
# PL 限制状态
cat /sys/class/powercap/intel-rapl:0/constraint_0_power_limit_uw  # 与场景值比对
# 频率是否被压
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
```
注意：MSR 只读安全（rdmsr），不写。GUI 通过 sudoers 白名单调用 helper 脚本。

### 3.2 通知（H1）
```python
from gi.repository import GLib
n = GLib.Notification.new("温度告警")
n.set_body(f"CPU {t}°C，接近限流阈值")
self.send_notification("thermal-warning", n)
```

### 3.3 数据落盘格式（G3/B1）
```
data/perf_YYYYMMDD.tsv:  HH:MM:SS \t freq_max \t temp \t pkg_W \t core_W \t throttle_bits
data/batt_YYYYMMDD.tsv:  HH:MM:SS \t cap% \t rate_W \t status
```
保留 7 天，启动时清理过期。

### 3.4 cgroup 应用功耗（R1）
```
/sys/fs/cgroup/system.slice/xxx.service/cpu.stat  # usage_usec 差分
```
按 CPU 时间占比 × package 功耗估算；图形应用经 `.scope` 单元归组。

## 六、风险与铁律遵守
- 所有 MSR 操作**只读**（rdmsr），不写 MSR（死机史）
- 不碰 EC（fan_boost=死机4）、不跑 stress-ng（死机2/3）
- 新增 root 操作全部走 sudoers 白名单 + kernel_guard 可自检
- 每批实施前跑备份脚本（00_保存会话与日志.sh）
