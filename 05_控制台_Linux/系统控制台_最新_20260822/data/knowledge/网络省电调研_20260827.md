## 二、方案清单（按预期收益排序）

### 方案 1: WiFi Power Save 调优 [推荐实测]

**原理**: ath10k 驱动的 802.11 电源管理控制 WiFi 无线电在空闲时进入低功耗状态。

**关键发现**:
- QCA9377 的 ath10k 驱动在 power_save=on 时，**多个用户报告吞吐量下降 30-50%**，且 CPU 唤醒增多
- PowerTOP 的 WiFi 功耗读数**不准确**（多处权威来源确认）——它基于模型估算而非实测传感器
- 真正的功耗差异需要用外部功率计测量整机放电率

**实施选项**:
```
# 选项 A: 关闭 WiFi 省电（推荐测试）
sudo iw dev wlp3s0 set power_save off
# 持久化:
echo -e "[device]\nwifi.powersave = 2" | sudo tee /etc/NetworkManager/conf.d/99-no-wifi-powersave.conf
sudo systemctl restart NetworkManager

# 选项 B: 开启 WiFi 省电（如果空闲功耗确实高）
sudo iw dev wlp3s0 set power_save on
# 持久化: wifi.powersave = 3 (当前已设置)
```

**真实案例**:
- Ubuntu 25.04 论坛: power-profiles-daemon 切 balanced 时自动设 `powersave=3`，导致 Intel WiFi 吞吐降至 ~5Mbps
- Arch 论坛: QCA9377 用户关闭 power_save 后，2.4GHz 速度从 14Mbps 升至 20Mbps，5GHz 从 11Mbps 升至 40Mbps
- Fedora 论坛: QCA9377 关闭 power_save 后速度翻倍

**风险**: 低。仅影响 WiFi 延迟和功耗，不影响系统稳定性。

**预期收益**: 整机空闲功耗可能变化 ±0.5-2W（取决于实际使用模式）。

---

### 方案 2: 5GHz vs 2.4GHz 频段选择 [有条件推荐]

**原理**: 5GHz 射频功耗通常比 2.4GHz 高，但传输效率更高（相同数据量完成更快→更早返回低功耗）。

**实测数据** (Toradex iMX8M Mini，三组对比):
| 场景 | 2.4GHz 功耗 | 5GHz 功耗 | 差异 |
|------|------------|----------|------|
| iperf3 无屏幕 | 3.84W | 3.26W | 5GHz 省 0.58W |
| CPU+iperf3 | 4.74W | 3.65W | 5GHz 省 1.09W |
| 最大压力+iperf3 | 5.18W | 4.33W | 5GHz 省 0.85W |

**矛盾案例**: XDA 论坛 Exynos 手机: 5GHz 比 2.4GHz 耗电快 3 倍（信号弱时）。

**结论**: 信号强时 5GHz 更省电（传输快→早休眠），信号弱时 2.4GHz 更省电（穿透好→不需要高功率发射）。

**建议**: 保持当前 5GHz 连接（如果路由器支持），不建议为省电切换到 2.4GHz。

### 方案 3: 蓝牙已禁用 [已完成]

**状态**: 已通过 rfkill soft-block 蓝牙（状态 1 和 2 均显示 Soft blocked: yes）。

**额外措施** (如果需要):
```
# 禁用蓝牙 USB autosuspend（如果蓝牙未使用）
echo "options btusb enable_autosuspend=N" | sudo tee /etc/modprobe.d/bluetooth.conf
```

**预期收益**: ~0.1-0.3W（蓝牙未使用时影响小）。

---

### 方案 4: 以太网口未使用时关闭 [不适用]

**原理**: 未插网线的以太网口如果保持 UP 状态，会消耗 1-6W（powertop 报告）。

**但**: 
- PowerTOP 的以太网功耗读数**已知不准确**（Arch 论坛确认）
- 实际测试: 关闭以太网口仅节省 ~1.5W（而非 powertop 报告的 3-6W）
- 本机以太网口 `enp2s0` 状态: 未确认，需检查

**建议**: 检查以太网口是否 UP，如果 UP 且未使用，可以关闭。

---

### 方案 5: PCIe ASPM [高风险，不推荐]

**原理**: PCIe Active State Power Management 允许 PCIe 设备在空闲时进入低功耗状态。

**真实案例**:
- Realtek r8169: ASPM 被驱动默认禁用，导致 CPU 无法进入 PC6/PC7 深度睡眠，空闲功耗从 8W 升至 13W
- T2 MacBook: 启用 ASPM 后，空闲功耗从 8W 降至 4.5W
- 但: ASPM 在某些硬件上导致随机链路失败和系统挂起

**风险**: 高。可能导致 WiFi 断连或系统不稳定。

**建议**: 不推荐在生产环境使用。

---

### 方案 6: TLP/PowerTOP 自动调优 [谨慎推荐]

**原理**: TLP 和 PowerTOP 可以自动应用一系列省电设置。

**但**: 
- Arch 社区: "TLP 和 PowerTOP 对功耗没有显著正面或负面影响"
- Framework 社区: "TLP/PowerTOP 的省电效果不足以产生可测量的差异"
- 可能与我们的场景系统冲突

**建议**: 不推荐安装 TLP（与 acdc-profile 重叠）。PowerTOP 可作为诊断工具。

## 三、信息陷阱警告

### ⚠️ 陷阱 1: PowerTOP WiFi 功耗读数不可靠
- **多处权威来源确认**: PowerTOP 的 per-device 功耗是模型估算，不是实测
- **实际验证**: 关闭 WiFi 后整机功耗可能仅变化 0.5W（而非 PowerTOP 报告的 5-9W）
- **正确方法**: 用外部功率计测量整机放电率

### ⚠️ 陷阱 2: "关闭 WiFi 省电 = 更省电" 不一定成立
- 关闭 802.11 power save → WiFi 无线电保持高功耗
- 但 → 吞吐量更高 → 传输完成更快 → CPU 更早休眠
- **净效果取决于使用模式**: 轻度使用可能更省电，重度使用可能更耗电

### ⚠️ 陷阱 3: iwlmvm power_scheme 对 QCA9377 无效
- `power_scheme=1/2/3` 是 Intel iwlwifi 驱动的参数
- QCA9377 使用 ath10k 驱动，参数完全不同
- **不要混淆 Intel 和 Qualcomm 的配置**

### ⚠️ 陷阱 4: 固件版本影响功耗
- ath10k 固件 bug 可能导致功耗异常（如 S5 关机后漏电 0.5W）
- firmware-5.bin vs firmware-6.bin 可能有功耗差异
- **建议**: 保持当前固件，不主动降级

## 四、结论

**最值得实测的方案**: 方案 1（WiFi Power Save 调优）—— 改动最小，风险最低，但实际收益需要用外部功率计验证。

**不推荐的方案**: 方案 5（PCIe ASPM）—— 风险过高。

**已完成的方案**: 方案 3（蓝牙禁用）。

**信息陷阱**: PowerTOP 的 WiFi 功耗读数不可靠，不要基于它做决策。
