## 二、性能瓶颈分析

```
性能天花板 = min(CPU 功耗墙, 散热能力, 固件限制)

当前实际限制排序:
  1. 散热瓶颈   → 满载 86°C → thermal throttle → 降频
  2. PL1 功耗墙 → 15W → 限制持续性能 (满载 ~2.5GHz)
  3. 离电供电墙  → 8W → 离电锁 1.6GHz (固件级,不可软件突破)
  4. 内存带宽   → 非对称双通道有轻微影响
  5. 后台进程   → Firefox/OpenCode 占用 30-50% CPU
```

## 四、C-State 深度休眠详解

| C-State | 唤醒延迟 | 节能效果 | 适用场景 |
|---------|---------|---------|---------|
| C0 (活跃) | 0µs | 无 | 满载工作 |
| C1 | 1µs | ~10% | 低延迟需求 |
| C1E | 2µs | ~20% | 日常使用 |
| C3 | 59µs | ~40% | 平衡模式 |
| C6 | 124µs | ~60% | 省电模式 |
| C7/C8 | 200+µs | ~70% | 深度省电 |
| C9/C10 | 500+µs | ~80%+ | 极限省电 |

**关键**: C-State越深,唤醒延迟越高。音频/实时应用需限制C-State深度。

## 五、EPP 能效偏好详解

| EPP值 | 数值 | 描述 | 频率行为(i5-8250U) |
|-------|------|------|-------------------|
| `performance` | 0 | 最大性能 | 1.6-3.4GHz (激进Turbo) |

| `power` | 255 | 最大省电 | 0.8-1.6GHz (极少Turbo) |

### 6.1 插电高性能 (AC Performance)

**适用**: 编译、渲染、视频编码、跑分测试

| 参数 | 配置 | sysfs命令 |
|------|------|----------|
| Governor | performance | `echo performance > /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor` |
| EPP | performance | `echo performance > /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference` |
| PL1 | 25W | `echo 25000000 > /sys/class/powercap/intel-rapl:0/constraint_0_power_limit_uw` |
| PL2 | 25W | `echo 25000000 > /sys/class/powercap/intel-rapl:0/constraint_1_power_limit_uw` |
| Turbo | ON | `echo 0 > /sys/devices/system/cpu/intel_pstate/no_turbo` |
| C-State | C1 | `for i in 3 4 5 6 7 8 9 10; do echo 1 > /sys/devices/system/cpu/cpu0/cpuidle/state${i}/disable 2>/dev/null; done` |
| thermald | 禁用 | `sudo systemctl stop thermald` |
| WiFi PM | OFF | `sudo iw dev wlp3s0 set power_save off` |
| USB AS | OFF | `echo -1 > /sys/bus/usb/devices/*/power/autosuspend` |

**预期效果**: 满载3.0+GHz,性能最大化

### 6.2 插电平衡 (AC Balanced)

**适用**: 日常办公、网页浏览、轻度开发

| 参数 | 配置 | sysfs命令 |
|------|------|----------|
| Governor | powersave | `echo powersave > /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor` |
| EPP | balance_performance | `echo balance_performance > /sys/devices/system/cpu/cpu*/cpufreq/energy_performance_preference` |
| PL1 | 15W(默认) | 不变 |
| PL2 | 25W | `echo 25000000 > /sys/class/powercap/intel-rapl:0/constraint_1_power_limit_uw` |
| Turbo | ON | `echo 0 > /sys/devices/system/cpu/intel_pstate/no_turbo` |
| C-State | C3 | 限制到C3 |
| thermald | 默认 | 保持运行 |
| WiFi PM | OFF | `sudo iw dev wlp3s0 set power_save off` |
| USB AS | ON(2s) | `echo 2 > /sys/bus/usb/devices/*/power/autosuspend` |

**预期效果**: 平衡性能与功耗,满载2.5-3.0GHz

## 八、自动化切换方案

### 8.1 TLP 自动切换(最简单)

TLP 在 AC/电池切换时自动应用对应配置,无需额外脚本。

### 8.2 udev 规则 + 自定义脚本

```bash
# /etc/udev/rules.d/99-power-switch.rules
SUBSYSTEM=="power_supply", ATTR{type}=="Mains", ATTR{status}=="Discharged", RUN+="/usr/local/bin/on-battery.sh"
SUBSYSTEM=="power_supply", ATTR{type}=="Mains", ATTR{status}=="Charged", RUN+="/usr/local/bin/on-ac.sh"
```

### 8.3 systemd + acpi_listen

```bash
acpi_listen | while read line; do
  case "$line" in
    "ac_adapter"*) /usr/local/bin/on-ac.sh ;;
    "battery"*)    /usr/local/bin/on-battery.sh ;;
  esac
done
```

### 8.4 PPD D-Bus API

```python
import dbus
bus = dbus.SystemBus()
proxy = bus.get_object('org.freedesktop.UPower.PowerProfiles', '/org/freedesktop/UPower/PowerProfiles')
proxy.Set(dbus.String('ActiveProfile'), dbus.String('performance'))
```

## 十、推荐执行路径

### 路径A: 快速上手(免费,无root)

1. 设置电源档位: `powerprofilesctl set performance/balanced/power-saver`
2. 关闭后台进程: Firefox/mintinstall
3. 切换场景: 使用 `05_一键性能模式.sh`

### 路径B: 深度优化(需root)

1. **先清灰换硅脂**(¥30) → 降温10-15°C
2. **提升PL1** → 15W→25W(+40-60%性能)
3. **CPU降压** → -100mV(降温5-10°C)
4. **关闭mitigations** → +5-10%性能
5. **安装TLP** → 精细电源管理
6. **配置thermald** → 温度控制

### 路径C: 极限性能(需root+硬件操作)

1. 清灰换硅脂 + 散热底座
2. PL1提升至25W + CPU降压-100mV
3. 关闭mitigations + 优化GRUB参数
4. 预期: 满载3.0+GHz,性能翻倍

### 13.3 关键发现

#### 发现1: Balanced 反而比 Performance 更快(+2.4%)

```
Balanced:    1384.6万/s  (66°C → 78°C, 2796 → 2600MHz)
Performance: 1352.3万/s  (72°C → 79°C, 3400 → 2599MHz)
```

**原因分析**:
- Performance 模式测试前已达 **72°C**(之前连续测试导致热量积累)
- 高起始温度 → 更快触发 thermal throttle → 频率从 3400MHz 暴跌至 2599MHz(-23.6%)
- Balanced 起始温度仅 66°C → 有更大散热余量 → 频率仅下降 196MHz(-7%)
- **结论**: 在散热瓶颈(86°C)下,盲目追求 Performance 模式反而适得其反

#### 发现2: Power-Saver 性能仅为其他两档的 29%

```
Power-Saver: 404.6万/s  (53°C → 56°C, 800 → 900MHz)
Performance: 1352.3万/s  → 3.34倍差距
```

**原因分析**:
- EPP=power 将频率锁定在 **800MHz**(基频的50%)
- 测试期间温度仅上升 3°C → 几乎无热节流
- 但性能代价巨大: **-70.8%** 吞吐量
- **结论**: 离电省电模式严重牺牲性能,仅适合极限续航场景

#### 发现3: 温度-频率-性能三维关系实测

```
实测数据点:
┌─────────┬────────┬──────────┬──────────┐
│ 起始温度 │ 结束温度 │ 起始频率  │ 吞吐量   │
├─────────┼────────┼──────────┼──────────┤
│   53°C  │  56°C  │  800MHz  │ 404.6万  │ ← Power-Saver
│   66°C  │  78°C  │ 2796MHz  │ 1384.6万 │ ← Balanced
│   72°C  │  79°C  │ 3400MHz  │ 1352.3万 │ ← Performance
│   80°C  │  86°C  │ 2700MHz  │ 962.7万  │ ← 基线(热量积累)
│   65°C  │  81°C  │ 2400MHz  │ 1213.5万 │ ← 早期测试
│   63°C  │  84°C  │ -        │ 1315.8万 │ ← 冷却后
└─────────┴────────┴──────────┴──────────┘

趋势:
- 起始温度 <60°C → 可充分发挥性能
- 起始温度 60-70°C → 性能开始受限
- 起始温度 >70°C → 严重热节流
- 起始温度 >80°C → 性能下降 25-35%
```

#### 发现4: 热积累效应

```
连续测试性能衰减:
测试1 (冷启动): 1315.8万/s  ← 最佳
测试2 (间隔3s): 1213.5万/s  ← -7.8%
测试3 (间隔0s):  882.0万/s  ← -33.0%
测试4 (间隔0s):  737.3万/s  ← -44.0%

每连续一次测试,性能下降约 7-15%
原因: 温度累积 → thermal throttle 加剧
```

### 13.5 优化建议(基于实测)

#### 优先级排序

| 优先级 | 操作 | 预期收益 | 理由 |
|--------|------|---------|------|
| **1** | 清灰换硅脂 | +15-25% | 实测86°C是最大瓶颈,降至70°C可避免节流 |
| **2** | 提升PL1(需清灰后) | +40-60% | 15W→25W,但必须先降温 |

| **4** | 关闭mitigations | +5-10% | 纯软件优化,无硬件风险 |

#### 场景切换策略(基于实测数据)

