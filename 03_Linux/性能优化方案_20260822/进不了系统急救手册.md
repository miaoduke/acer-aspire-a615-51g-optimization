# 进不了系统（开机崩溃/黑屏/无限重启）急救手册
适用: i5-8250U + Arch/Debian 系 Linux, intel-undervolt 降压机
最后更新: 2026-08-15 (2026-08-13 超压事故后编写, 2026-08-13 补全, 2026-08-15 增加会话备份原则)

## 0. 预防（永远优先）
0. **会话备份原则**：每次执行下一个新任务前, 先运行
   `性能优化方案/会话备份/00_保存会话与日志.sh` 保存会话+系统日志（详见 SOP 第 13 章）。
   崩溃后对照备份目录里的 `cpu_power_snapshot.txt`/`services_status.txt`/`session/` 快速定位。
1. conf 永远只保留已验证安全值 (本机: -100mV), 测试档绝不写入 conf (用命令行临时 apply)
2. intel-undervolt.service 开机自动应用 conf → conf 安全 = 开机安全
3. 每次改 conf 前备份: cp /etc/intel-undervolt.conf /etc/intel-undervolt.conf.bak-<描述>
4. 手头保留恢复 U 盘 (带原版系统镜像/U盘安装盘)

## 1. 症状判断
| 症状 | 最可能原因 |
|------|-----------|
| 转圈后无限重启/黑屏 | service 开机应用了危险电压 (conf 有误) |
| 卡死在某处无反应 | 电压过低不稳 (崩溃前) |
| 能进 grub 但内核 panic | 电压过低 / 文件系统损坏(硬断电引起) |

## 2. 急救流程（从上到下尝试）

### 2.1 Grub 菜单 → 编辑内核启动参数（最快，不依赖 U 盘）
1. 开机见到 GRUB 菜单（提示 Esc 或直接显示）→ 按 **e** 编辑
2. 找到 `linux ...` 开头那行（含 vmlinuz 的行）
3. 行尾追加: `systemd.unit=emergency.target`
   - 紧急模式(最小环境)。若想更小: 直接替换为 `init=/bin/bash`
4. 按 **Ctrl+X** 或 **F10** 启动
5. 进入 emergency shell / bash 后, 根分区可能是只读 → 重新挂载读写:
   - `mount -o remount,rw /`  (emergency 模式通常已 rw)

### 2.2 在紧急 shell 中禁用超压 + 恢复安全 conf（核心动作）
```sh
# 1. 永久禁用开机降压 (防止重启循环)
systemctl disable --now intel-undervolt.service

# 2. 校验当前 conf (任何非负值=危险)
cat /etc/intel-undervolt.conf

# 3. 恢复安全值 (写死 -50mV, 最保险; 或你记录的安全值)
cat > /etc/intel-undervolt.conf << 'EOF'
undervolt 0 "CPU" -50
undervolt 1 "GPU" -50
undervolt 2 "CPU Cache" -50
undervolt 3 "System Agent" 0
undervolt 4 "Analog I/O" 0
EOF

# 4. 若手头有已知可用备份: 
# cp /etc/intel-undervolt.conf.bak-50mv /etc/intel-undervolt.conf

# 5. 检查/修复文件系统 (硬断电可能损坏)
fsck -y /    # 根分区; 先 umount 或只读状态下执行; 若根在运行则跳过或改在 2.3 做

# 6. 重启
reboot
```

### 2.3 连 emergency 也进不去 → 使用恢复 U 盘 / 安装盘 live 模式
1. 启动 U 盘 → 选 "Try/Live" 进图形/Live 环境
2. 挂载根分区 (先 lsblk 找分区, 如 /dev/sda2):
```sh
sudo lsblk
sudo mount /dev/sda2 /mnt
cd /mnt/etc
nano intel-undervolt.conf    # 按 2.2 步骤 3 改回安全值
```
3. 可选: 禁服务 (chroot 操作较繁, 改 conf 已足够, 因为 service 只应用 conf)
4. 卸载并重启: `sudo umount /mnt && sudo reboot`

### 2.4 文件系统损坏处理（fsck）
- 进 emergency 后: `fsck -y /dev/sda2`（读根分区设备名以 lsblk 为准）
- 若报大量错误需多次执行: `fsck -y /dev/sda2 && fsck -y /dev/sda2`

## 3. 重启成功后确认
1. `intel-undervolt read | head -1` → 应是安全值 (-50~-100mV)
2. `sudo dmesg | grep -iE "mce|machine check"` → 计数不应暴涨
3. 数据盘: `sudo mount -t ntfs-3g /dev/sdb1 /media/<USER>/Public`
4. 重新启用降压服务时: 先确认 conf 安全, 再 `systemctl enable --now intel-undervolt`

## 4. 本机关键备份（事故前就位）
- /etc/intel-undervolt.conf.bak-50mv  (可用安全值)
- 本手册: 性能优化方案/进不了系统急救手册.md
- 扫描数据: 性能优化方案/sweep_data/  (数据盘, 重启不丢)
- **会话备份: 性能优化方案/会话备份/<时间戳>/** (数据盘, 含系统日志+会话内容, 重装系统后最先查看)
  - 重装后查验顺序: MANIFEST.md → system_logs/cpu_power_snapshot.txt → services_status.txt → session/
