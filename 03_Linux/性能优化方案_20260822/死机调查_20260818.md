## 二、屏幕证据（用户目击，关键）

```
Kernel panic - not syncing: ...
...（一串）
timeout: not all cpus entered broadcast exception handler
please reboot your computer!
```

### 技术解读

| 文本 | 来源 | 含义 |
|------|------|------|
| `Kernel panic - not syncing` | Linux 内核 | 内核致命错误，终止运行 |
| `timeout: not all cpus entered broadcast exception handler` | **内核 MCE 机制**（`arch/x86/kernel/cpu/mce/core.c`） | 机器检查异常（Machine Check）广播后，部分 CPU 未在超时内进入异常处理程序 → **硬件级错误** |
| `please reboot your computer!` | Acer 固件（BIOS/EC） | 固件层对硬件错误的配套提示 |

**结论**: 这是 **MCE（机器检查异常）触发的内核 panic**，属于硬件级错误（CPU/内存/供电域计算错误），**不是**软件崩溃（驱动/OOM/用户态）。

## 四、根因分析

### 4.1 嫌疑排序

| 嫌疑 | 依据 | 强度 |
|------|------|------|
| **① 降压 -105mV 过深 → CPU 空闲电压不足触发 MCE** | ① 12.1 教训：**冻结发生在满载后的空闲/冷却期**（空闲时电压请求最低，降压偏移易跌破阈值）；② MCE 正是降压过深的典型症状；③ 死机时机完全吻合（满载 70°C 后冷却期）；④ 12.4 定稿规则："**冻结则退回 -100**"；⑤ 08-17 死机 #2/#5 也发生在 -105mV 生效期间 | 🔴 **最高** |
| ② 内存混插（Hynix 4G + Kingston 8G） | 内存错误同样走 MCE 通道；手册预判"AC 也死 → 内存/主板"；#6 为首次 AC 死机，嫌疑升级 | 🟡 中 |
| ③ nvidia 驱动挂起 | 死机 #1 同模式（nvidia）；但 #6 为 MCE panic 而非驱动调用栈 | 🟢 低 |
| ④ EC/固件（BIOS V2.02 已最新） | 无新版本可更新（官方停更）；历史死机多为 DC，本次 AC 排除供电链路假说 | 🟢 低 |

### 4.2 假说更新（重要）

**旧假说（08-17）**："DC 供电链路问题"（5 次死机 4 次 DC）—— **被 #6 推翻/弱化**：
- #6 在 AC 下死机 → 不再是"仅 DC"问题
- 更统一的解释：**降压 -105mV 在低电压请求窗口（空闲/轻载）触发 MCE**，与供电模式无必然关系（DC 死机恰逢 -105mV 生效期）
- 12.4 定稿本身就带观察期与回退规则，本事件是规则的**首次执行**

## 五、处置（已执行）

```bash
# ① 降压回退 -105mV → -100mV（12.4 规则）
sudo sed -i 's/-105/-100/g' /etc/systemd/system/intel-undervolt.service
sudo systemctl daemon-reload && sudo systemctl restart intel-undervolt
# 验证: undervolt --read → core/gpu/cache = -99.61mV ✅

# ② panic 自动重启（避免挂死屏幕）
sudo sysctl -w kernel.panic=10
echo "kernel.panic=10" | sudo tee /etc/sysctl.d/99-panic.conf

# ③ 数据盘重挂载（重启后丢失）
sudo mount -t ntfs-3g /dev/sdb1 /media/<USER>/WS
```
