## 三、M1 带电极致性能模式（AC + 独显）

### 配置（当前已生效，无需操作）
```bash
powerprofilesctl set performance        # EPP=performance
# PL=25W/25W、Turbo ON、降压 -50mV 由服务自动保持（2026-08-29 实测校正，原写 -100mV）
```

### 实测数据（2026-08-18）

> ⚠️ 本表为 **2026-08-18 在 -100mV 下** 采集。**当前配置为 -50mV**（2026-08-29 实测），
> 故下表中 `@-50mV` 那一行（1731.6万/s）才是**最接近当前状态**的参考值。
> 引用其余行时须注明其测试当时配置。

| 配置 | 吞吐 | 温度 | 对照 |
|------|------|------|------|
| **AC+独显 @25W/-50mV** | **1731.6万/s** | 72°C | 08-16 PL 探针 — **最接近当前配置** ⭐ |
| AC+独显 @25W/-100mV | 1707.2万/s（1729.3/1685.0） | 71°C | 08-18 实测（当时配置） |
| AC+独显 @25W/-105mV | 1680.2万/s | 70°C | 死机前测（数据有效） |

- 满载温度 71°C，余量充足（crit=100°C）

## 五、M3 离电效能模式（DC + power-saver）

### 配置（⚠️ 需停用 acdc-profile，见下）
```bash
# 一键脚本 v2.0（桌面 m3.sh / 测量脚本目录 m3.sh）:
./m3.sh on        # 进入 M3：停+禁用 acdc-profile、切 power-saver、创建开机保持服务
                  # 可选: GPU 引导(推荐集显, 切换自动重启, 10s反悔窗口, 空格跳过等待)
./m3.sh off       # 退出 M3：按供电自动回 M1/M2、恢复 acdc-profile、移除持久化服务
                  # 可选: 集显时询问切回独显(自动重启, 10s反悔窗口, 空格跳过等待)
./m3.sh status    # 查看当前状态

# v2.0 持久化机制: 重启后 M3 自动保持
#   · acdc-profile 被 disable(不复活) + m3-power-saver.service(enabled) 开机自动设回 power-saver
#   · off 时自动清理(m3 服务删除 + acdc-profile enable)
#   · 2026-08-18 完整测试通过: 切集显重启后 power-saver 保持 ✅ / 切回独显重启后零残留 ✅

# 等价手动命令:
sudo systemctl stop acdc-profile        # 必须：守护会 30s 内强制改回 balanced（实测 10:32:21 日志实证）
sudo systemctl disable acdc-profile     # 重启后不复活
powerprofilesctl set power-saver        # EPP=power
# 可选省电加强: echo 10000000 | sudo tee /sys/class/powercap/intel-rapl:0/constraint_0_power_limit_uw
# 恢复: powerprofilesctl set balanced && sudo systemctl enable --now acdc-profile
```

### 实测数据（2026-08-18，DC+独显）

| 场景 | 整机功耗 | 频率 | 温度 | 说明 |
|------|---------|------|------|------|
| 空闲 60s | **23.6W** | 800MHz | 55°C | 实测（与 M2 无差异） |
| 轻载（1线程 20s） | **19.2W** | 锁 800-900MHz | ~55°C | 实测，吞吐 32360 次（**-52%**） |
| 满载（历史） | — | 800-900MHz | ~61°C | ~400万/s（锁频） |

### 关键结论
- **空闲时 M3 与 M2 功耗几乎相同**（23.6 vs 23.7W）——空闲功耗瓶颈不在 CPU EPP（两者都深度降频），而在独显+桌面+后台
- **M3 的收益在轻载/中载场景**：轻载省 ~4.5W（24.5→19.2W），代价是性能减半
- **M3 若用集显，可再省 ~7-8W**（历史集显空闲 ~16W vs 独显 23.7W）→ 这才是 M3 最大的省电杠杆

## 六、GPU（独显/集显）变量分析

| 场景 | 独显（nvidia） | 集显（intel） | 差异 | 建议 |
|------|---------------|--------------|------|------|
| 满载吞吐（AC） | **1707.2万/s** @71°C | 1663.8万/s @60°C | 独显 +2.7% | 性能场景用独显 |
| 空闲整机功耗（DC） | **23.7W** | ~16W（历史） | 集显省 **~7.7W** | 续航场景用集显 |
| 稳定性风险 | ⚠️ nvidia 580.173.02 有挂起史（死机#1） | 稳定 | — | 日常可切集显 |

### 机制（历史四象限实证）
- 独显 MX150 **独立供电**，不占 CPU 的 RAPL 包功耗 → CPU 得满 25W → 计算更快
- 集显 iGPU 与 CPU **共享包功耗** → 渲染分走部分功率 → CPU 计算略慢，但总功耗更低、更凉快

### 最终决策（用户指定）
- **带电默认独显** ✅ 已配置（prime-select = nvidia）
- 离电：M2 默认独显（性能优先）；M3 推荐集显（若接受 2 次重启切换：`sudo prime-select intel` + 重启 ×2）
- 切换回独显：`sudo prime-select nvidia` + 重启 ×2

## 七、⚠️ 死机事件记录（2026-08-18，死机 #6，本项目首次 AC 死机）

### 事件
- 09:41:05（AC 供电，nvidia 模式，-105mV 生效中）：基线测试完成后硬死机
- 屏幕显示：**`Kernel panic - not syncing: ...` + `timeout: not all cpus entered broadcast exception handler` + `please reboot your computer!`**
- 证据：journal 无关机序列截断 / pstore 空（efi_pstore 不写盘）/ MCE 磁盘计数 0（panic 未落盘）

### 根因判断
- `not all cpus entered broadcast exception handler` = **MCE（机器检查异常）广播处理超时**，典型硬件级错误 panic
- 结合 12.1 教训（冻结发生在满载后空闲/冷却期=电压请求最低时跌破阈值）+ 12.4 定稿规则（"冻结则退回 -100"）→ **判定 -105mV 降压过深**，已按规则回退 **-100mV**

### 已执行修复
```bash
sudo sed -i 's/-105/-100/g' /etc/systemd/system/intel-undervolt.service  # 服务改 -100
sudo systemctl daemon-reload && sudo systemctl restart intel-undervolt   # 热应用（实测 -99.61mV）
sudo sysctl -w kernel.panic=10                                            # panic 后自动重启
```

### 复测验证（-100mV）
- AC+独显 @25W/-100mV：**1707.2万/s**，71°C，2 轮稳定无死机 ✅
- 性能与 -105mV 无实质差异（+1.6% 噪声内），换取历史验证的稳定性

### 后续观察（重要）
- 若再死机一次 → 转内存路线：memtest86+ 或拔一条内存单测（混插嫌疑：Hynix 4G + Kingston 8G）
- 观察期内避免任何 DC 满载测试（历史红线，保持）
- 下次 panic 请**拍照留存**（系统无转储能力）
