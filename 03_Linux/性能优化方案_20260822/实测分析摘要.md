## 核心数据对比

### 三档电源模式(完整测试,冷启动)

| 模式 | EPP | 起始温度 | 结束温度 | 起始频率 | 吞吐量 | 相对性能 |
|------|-----|---------|---------|---------|--------|---------|
| **Balanced** | balance_performance | 66°C | 78°C | 2796MHz | **1384.6万/s** | **100%** |
| **Performance** | performance | 72°C | 79°C | 3400MHz | 1352.3万/s | 97.7% |
| **Power-Saver** | power | 53°C | 56°C | 800MHz | 404.6万/s | 29.2% |

### 关键结论

1. **Balanced > Performance** (+2.4%)
   - 原因: Performance起始温度72°C(热积累),触发thermal throttle
   - Balanced起始温度66°C,有更大散热余量
   - **教训: 温度管理比电源模式更重要**

2. **Power-Saver 性能仅为 29%**
   - EPP=power 锁定800MHz,完全牺牲性能
   - 温度仅上升3°C → 几乎无热节流
   - **仅适合极限续航场景**

3. **热积累效应显著**
   - 连续测试: 1315→1213→882→737万/s
   - 每次测试性能下降7-15%
   - **建议: 测试间隔至少10秒冷却**

## 温度-频率-性能三维关系

```
实测数据点:
┌─────────┬──────────┬──────────┬──────────┐
│ 起始温度 │ 结束频率  │ 温度上升  │ 吞吐量   │
├─────────┼──────────┼──────────┼──────────┤
│   53°C  │  900MHz  │   +3°C   │ 404.6万  │ ← Power-Saver
│   66°C  │ 2600MHz  │  +12°C   │ 1384.6万 │ ← Balanced ★最佳
│   72°C  │ 2599MHz  │   +7°C   │ 1352.3万 │ ← Performance
│   80°C  │ 2400MHz  │  -19°C   │  962.7万 │ ← 热量积累
│   86°C  │ 2400MHz  │    0°C   │  882.0万 │ ← 连续测试
└─────────┴──────────┴──────────┴──────────┘

关键阈值:
- <60°C: 完全Turbo,最佳性能
- 60-70°C: 正常Turbo,性能良好
- 70-80°C: 开始节流,性能受限
- >80°C: 严重节流,性能下降25-35%
```

## 优化建议(基于实测)

### 立即可做(无需root)

1. **场景自动切换**
   - 温度<60°C → Performance模式
   - 温度60-70°C → Balanced模式(实测最佳)
   - 温度>70°C → Power-Saver模式
   - **预期收益: +10-15%**(避免热节流)

2. **关闭后台进程**
   - OpenCode占59% CPU
   - 测试/编译时关闭 → **+59%可用资源**
   - **预期收益: +30-50%**(满资源)

3. **测试间隔冷却**
   - 连续测试性能下降44%
   - 间隔10秒冷却 → 恢复最佳性能
   - **预期收益: +44%**(避免热积累)

### 需要root

4. **清灰换硅脂**(¥30)
   - 实测86°C是最大瓶颈
   - 降至70°C → 恢复完全Turbo
   - **预期收益: +15-25%**

5. **提升PL1**(15W→25W)
   - 必须先清灰降温
   - 温度<70°C时提升 → 安全
   - **预期收益: +40-60%**

6. **CPU降压 -100mV**
   - 降温5-10°C
   - 为PL1提升留余量
   - **预期收益: +5-10%**(间接)
