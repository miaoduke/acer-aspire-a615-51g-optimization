# 电池保养模式调研与实施方案（2026-08-18）

> 调研方法：公开学术文献 + Linux 内核文档 + GitHub 项目 + 社区案例
> 本机：Acer Aspire A615-51G，LG 电池（设计 3220mAh；充电读数基线 2618mAh=81.3%；**协议采样真实健康度 78.85%（2026-08-20 11:59，放电 40-60% 窗口，2539mAh）**，已衰减 ~21%）

## 一、科学性结论：充电上限 80% 有充分学术依据 ✅

| 研究 | 结论 |
|------|------|
| MDPI 2018（NMC/LMO 电池，3 年测试） | 避免高 SOC 可延长寿命 **44-130%**；100% 满电存放 vs 15% 存放，日历老化贡献差异巨大 |
| RSC 2025（浮充-循环混合模式，2 年测试） | 4.2V 浮充电池 1 年后跌破 60% 容量；**限制充电电压（4.0V）是最有效的缓解手段**——限充 80% ≈ 电压限制 |
| IOP 2026（NCA 电池） | 0-80% 部分循环寿命 500 EFC vs 0-100% 全循环 333-337 EFC（**+50%**） |
| 中文综述 | 高 SOC 区间循环引发活性锂损失（LLI）和正极材料损伤，是衰减主因 |

**对本机的意义**：本机主要插电使用（M1 场景）→ 长时间 100% 浮充 = 最伤电池的场景之一（浮充-循环混合模式年衰减 >20% 的案例）。限充 80% 对"长期插电"用户收益最大。电池已衰减到 ~78.9%（协议采样真实值），继续满充存放会加速衰减（业界普遍以 80% 为寿命终点——**本机已跌破**，保养更迫切）。

## 三、技术方案：acer-wmi-battery 内核模块

**项目**：github.com/frederik-h/acer-wmi-battery（312 stars，GPL-2.0，实验性）
**功能**（对应 Windows Acer Care Center 的 Battery Health）：
- `health_mode`：**限充 80%**（EC 固件级行为，Linux 模块只是开关）
- `calibration_mode`：校准模式（先充 100% 再放再充，校准容量估算）
- `temperature`：读取电池温度

**工作原理**：绑定 GUID → WMI 方法调用（wmidev_evaluate_method，method 20）→ 设置 function_mask=1(health) + function_status → **EC 固件执行**。模块加载时**默认不改变任何设置**（安全设计）。

**社区验证**：
- Aspire 5 A517-52 成功：电池停在 80% 不再充满（TLP 显示 80.5%）
- Aspire 5 A515-45-R74N 成功：**关机状态也生效**（EC 级），双启动 Windows 下显示正常（个别工具读数异常但无害）
- 已知不支持：Aspire E15/E17、Travelmate p259（**这些机型没有该 GUID**——本机 GUID 存在，本质不同）
- 主流发行版有 DKMS/AUR/Copr 打包（Arch AUR、Fedora Copr），Linux 7.0 内核社区大量使用

**风险与对策**：
| 风险 | 等级 | 对策 |
|------|------|------|
| 模块加载无副作用（默认不改设置） | 无 | 加载后先读状态再启用 |
| health_mode 启用在无 GUID 机型上无效 | 低 | 本机 GUID 已验证存在 |
| 内核更新后模块失效 | 低 | DKMS 自动重建 |
| health_mode 重启后重置为 0 | 低 | modprobe 参数 enable_health_mode=1 + 开机检查 |
| 第三方代码信任 | 低 | 312 stars / 48 forks / 内核主线补丁同源（Jelle van der Waa 提交） |

## 六、实施结果：固件逆向调查（2026-08-18 实测）—— ❌ 本机硬件不支持

**部署尝试**：构建 acer-wmi-battery 模块成功（DKMS 签名安装），加载失败：
```
acer_wmi_battery: WMI battery status call returned a buffer of unexpected length 4
```

**ACPI 逆向（iasl 反编译 DSDT/SSDT）定位根因**：

| 步骤 | 发现 |
|------|------|
| GUID 定位 | 在 SSDT3（WMID 设备 "APGe"）_WDG 表中，ObjectID = **"BE"** → WMI 方法 `WMBE` |
| WMBE 方法实现 | **只处理 `Case (0x13)`**（查询类），其他命令一律置错误位返回 |
| 返回格式 | 固定 4 字节缓冲区（驱动要求 ≥8 字节结构体） |
| 健康模式命令 | **固件中不存在**（无 set 命令路径） |
| 固件版本 | V2.02（2019-01-03，最终版）——早于 Acer 健康模式功能（2020+ 机型固件才实现） |

**结论**：本机固件暴露的 79772EC5 GUID 仅用于电池信息查询（命令 0x13），**未实现电池健康模式（80% 限充）**。该功能随 Acer Care Center 在 2020 年后的机型才加入。固件已无更新（V2.02 为最终版）→ **硬件层面无法实现充电上限控制**。

**已清理**：DKMS 注册移除、自动加载配置删除、模块未加载。环境无残留。

## 八、深度调研补充（2026-08-19）：如何实现电池保养的完整答案

### 1. 固件层再挖一层 —— 温度读取大突破 ✅，限充彻底定案 ❌

| 步骤 | 发现 |
|------|------|
| 方法映射重新解读（_WDG + 方法 ID） | **WMBE 的 `Case 0x13` = method_id 19 = `get_battery_information`（SBS 信息查询），不是健康状态查询！** method 20（健康状态）无对应 Case，走 Default 错误分支返回 4 字节 → 之前 "unexpected length 4" 全部解释通 |
| WSMI 机制确认（ssdt3.dsl 1304 行） | `MTID=Arg0; WMIB=Arg1; WSSP=0xD0` —— Acer 固件标准 SMI 调用（Acer Care Center 同款），查询为只读路径，**安全** |
| **method 19 实测（2026-08-19，SBS 索引批量探测）** | **0x08 温度 = 36.9°C ✓**、0x09 电压 = 16837mV ✓、0x0A 电流 ✓、0x0F 剩余容量 ✓、0x18 设计容量 = 3220mAh ✓、0x19 设计电压 = 15200mV ✓ —— **电池温度原生可读！** |
| 永久部署 | acer-wmi-battery 模块改为只读注册（跳过 method 20 失败），`/sys/bus/wmi/drivers/acer-wmi-battery/temperature`（0444 全用户可读）+ `/etc/modules-load.d/` 开机加载 |
| 限充查询（method 20） | 固件无 Case 0x14 → BEBI[2]=1 错误位 → **健康模式不存在，限充定案 ❌** |
| 主线 v4 补丁（2026-05-31，Ratatoskr 存档） | DMI 白名单扩至 6 机型（A315-510P/24PT/44P/59/A715-42G 等），**仍无 A615-51G**；Armin Wolf 警告维持：不存在的 WMI 方法调用最坏可致 ACPI 固件崩溃 |

**定案更新**：硬件 80% 限充不可实现（固件无该命令）❌；但**电池真实温度读取已打通** ✅（method 19 查询，只读，Acer Care Center 同款接口）。

### 2. 内核层 —— 等待无意义

- 主线补丁（2026-05 v3）仍在 review，未进内核
- 即便并入：本机不在 DMI 白名单，只可能注册 v1（仅温度）扩展——而本机固件温度查询返回 BEBI 无温度 → 注册了也无数据
- **结论：内核路径关闭**

### 3. 行为层 —— 2025-2026 最新学术证据（这是唯一可执行杠杆 ✅）

| 研究 | 关键数据 | 对本机意义 |
|------|---------|-----------|
| IOP 2025 大规模老化研究（150+ 电池，NMC532，2020 启动仍在跑） | 0-100% 全循环平均 **3000 EFC** 到 80% SoH；**限制最大 SOC 80% → 6000+ EFC（循环寿命翻倍）**；0-40% 窗口 4500 EFC 后仍 90% SoH | 80% 限充是**最强**单因素，可惜本机硬件不支持 → 用行为模拟 |
| MDPI 2025（LFP，42 条件测试） | 日历老化由 SOC+温度主导；25°C 下 3C 快充析锂陡降；宽 SOC 窗口/高最大 SOC 加速衰减；中等窗口（25-75%）衰减大幅减缓 | 避免满电浮充 + 避免深放 = 行为层核心 |
| RSC JMCA 2025（LFP） | 高 SOC 存储损伤在后续循环中**持续放大**——日历老化是循环劣化的前兆 | 满电浮充的代价不止当天，会滚雪球 |
| arXiv 2026 建模（LG M50 NMC，本机同源 LG 电池） | **25°C + 100% 满电存放 → 5 个月跌破 80% SoH**；40°C 满电仅 2 个月；10°C+30% 12 个月仍 93% | 量化"满电浮充一天 ≈ 多少衰减"——最高优先级规避项 |
| ScienceDirect 2025（Ni-rich） | 低温存储时高 SOC 短期日历老化更快（CEI 机制细节） | 不改变大方向 |

**行为层结论**：本机最大衰减杠杆 = **满电浮充时间**。所有可执行措施围绕它展开。

### 限充最终铁证（2026-08-20 复核，不可翻案）

社区方案 acer-wmi-battery（Frederik Harwath）用 WMBE method 20/21（对应 Case 0x14/0x15）实现 80% 限充，在多机型验证成功（Aspire 5 A515-56 等，社区 2025-12/2026-04 案例）。**复核本机 SSDT9 反编译源码**：

```
Method (WMBE, 3, Serialized)
{
    CTID = 0x4542
    WSMI (Arg1, Arg2)            ← 无条件 SMI 前置
    Switch (ToInteger (Arg1))
    {
        Case (0x13) { BEBI = WMIB; Return (BEBI) }   ← 唯一 Case = method 19（温度/电压查询）
    }
    BEBI [0x02] = One            ← 其他全部（含 0x14 get / 0x15 set）→ 错误标志
    Return (BEBI)                ← 返回 4 字节错误码（解释了所有 "unexpected length 4"）
}
```

**结论**：本机固件（2018 版 BIOS）无 Battery Health Mode。成功案例均为新固件机型。限充维持"不可实现"，行为层策略为唯一杠杆。附带收益：确认"WMBE 无 Case → 4 字节错误码"模式，排查其他 WMI 方法可复用此判据。

## 九、学术精确化与改善清单（2026-08-20）

### 1. SOC 窗口衰减因子量化表（PHM 2025，归一化模型，可移植任意锂电）

| SOC 窗口 | 每等效循环衰减权重 | 解读 |
|----------|-------------------|------|
| 100-0 | 1.00000 | 基准（全循环） |
| 100-25 | 0.78750 | 上限 100 略好于全循环 |
| 100-50 | 0.43750 | **上限 50%：循环损伤仅全循环 43.75%** |
| 100-75 | 0.40625 | 高段小窗口（75-100）权重 0.41 |
| 75-25 | 0.68750 | 中等窗口 |
| 62.5-37.5 | 0.28125 | **中段窄窗口最优（0.28）** |
| 50-25 | 0.62500 | 中低段 |
| 25-0 | 1.00000 | **深放段损伤 = 全循环（必须避免 <20% 使用）** |
| 50-0 | 1.03125 | 低段窗口反而不利（低 SOC 高压差） |

**结论（量化）**：
- 上限每降 20%（100→80）循环寿命约翻倍（IOP 实测 3000→6000 EFC 交叉验证）
- **80% 上限 ≈ 0.5 权重**，是"收益/可用性"最优折中
- 25% 以下深放区权重 1.0——低电量提醒（20%/10%）科学依据

### 2. 充电温度与 CC-CV 行为（MDPI 2025，1.8C/4.35V 实验）

| 发现 | 数据 | 对本机意义 |
|------|------|-----------|
| CC-CV 转变点随老化前移 | 100% SoH→82.4% SOC、90%→79.9%、80%→77.2% | 本机 81.3% 健康度 → CV 约在 **~79-80%** 开始 |
| CV 阶段 = 高损伤区 | >80% SOC 后 DCIRc（充电内阻）重新上升 | **80% 提醒点 = 进入高损伤区的准确信号** |
| 充电温度峰值在 70-80% SOC | 中心温度峰值 ~28°C（1.8C） | 高温提醒在充电中后段最相关 |
| 快充析锂 | 25°C 下 3C 快充析锂陡降 | 本机 0.37C 慢充无此风险 |

### 3. 日历老化模型（JES 2025 高精度 SEM 对比 + arXiv 2026）

- 60°C + 100% SOC 存放 9 个月 → 电池鼓包（不安全）——极端组合警示
- 25°C 满电 ≈ 5 个月破 80% SoH（arXiv 2026 LG M50 同源）
- **温度每降 10°C 日历老化约减半**（Arrhenius）→ 充电/存放时避免高温
- 模型建议：BMS 集成 SEM 做衰减预测——本机用健康协议数据做等效（月度线性拟合）
