## 二、从优秀案例提炼的关键设计模式

1. **Profile 化配置**（CoreCtrl/TCC）：所有设置以"配置文件"为单位，可命名、可切换、可自动触发（按应用/按 AC-DC 状态），而不是散落的开关
2. **状态自动切换**（TCC/system76-power）：AC 供电与电池供电自动应用不同 profile；GameMode 为"临时优化+自动恢复"
3. **后台守护进程 + 前台 GUI**（TCC tccd / GameMode / system76-power daemon）：权限敏感操作由 daemon 执行，GUI 通过 D-Bus/接口通信，GUI 崩溃不影响设置
4. **Dashboard 一屏总览**（TCC/Mission Center）：温度、功耗、频率、风扇四大核心指标同时呈现
5. **托盘常驻 + 迷你视图**（Mission Center/GWE/CoreCtrl）：日常低打扰，点开即用
6. **历史数据曲线**（GWE/Mission Center）：近期趋势回放
7. **权限分层**（CoreCtrl Polkit）：普通操作免密，特权操作走 Polkit 规则
8. **资源占用克制**（btop <1% CPU、Mission Center ~40MB）：监控工具本身不成为负担

## 六、资源占用专项调研（补充：占用小/省电/高效/速度快）

> 用户关注点：本机为 i5-8250U 低压 U + 12GB RAM，idle 功耗已优化至 5.53W，
> 控制台软件自身必须做到"占用小、省电、高效、运行速度快"。

### 6.1 GUI 工具箱空窗口基线内存（szibele.com 实测）

| 技术 | 空窗口内存 | 结论 |
|---|---|---|
| TUI（turbo vision） | 1.3 MB | 终端方案天然最省 |
| GTK2 | 2.8 MB | — |
| **GTK3** | **5.0 MB** | 桌面 GUI 最省档 |
| GTK4（GSK 硬件加速） | 空窗低但渲染翻倍 | 见 6.2 |
| Qt | 17 MB | 重 |
| Electron（网页壳） | 74.6 MB | 排除 |
| JavaFX | 80 MB | 排除 |

### 6.2 GTK4 vs GTK3 关键差异：渲染器决定内存

- GTK4 默认 GSK 硬件加速渲染，在低端核显（本机 UHD620）上内存为 GTK3 的 **2-3 倍**（有应用实测 3 倍增长）
- **`GSK_RENDERER=cairo` 环境变量**可关闭 GTK4 硬件加速：实测 100+MB → 33MB（降 3 倍）、250MB → 140MB
- 结论：GTK4 想省内存必须 cairo 渲染；**GTK3 默认就是 Cairo，无此坑**

### 6.3 现有监控工具实测资源占用

| 工具 | 内存 | CPU | 备注 |
|---|---|---|---|
| htop | ~5 MB | 极低 | TUI |
| btop | ~20 MB | <1% | TUI，GPU 监控 |
| Glances | ~60 MB | 中 | Python+Web，重 |
| Mission Center（Rust+GTK4） | idle ~40 MB / 常态 **130-170 MB** | <0.5% | itsfoss/xda 实测常态 140-280MB |
| Resources（Rust+GTK4） | ~130-136 MB | 低 | GNOME Circle |
| Cinnamon 桌面本身 | ~70 MB | — | 参照系 |

### 6.4 采样频率 = 功耗（省电核心设计）

- 轮询工具每次唤醒 CPU 都是一次 voluntary context switch；**紧 10ms 定时器即使只有 0.1% CPU 也会因频繁唤醒显著耗电**（drain 项目实测观点）
- RAPL 高频轮询实证（arXiv 2026）：1kHz 采样时复杂工具 overhead 达 0.25%-46.75%；简单实现 + 低频采样 = 接近零开销
- 单次读取成本极低：rdmsr ~0.2-0.6µs，sys_read 系统调用 ~1.4µs —— **瓶颈不是读取本身，而是采样频率**
- PowerTOP 默认 20s 间隔测量即可完成诊断 → 监控软件默认低频采样完全够用
- 结论：**自适应采样**是省电关键 —— 前台 1-2s、后台/托盘 5-10s、窗口隐藏暂停；控制操作按需执行绝不轮询

### 6.5 方案资源对比与推荐

| 方案 | 预估常态内存 | CPU | 启动速度 | 省电性 | 开发成本 |
|---|---|---|---|---|---|
| Python + GTK3 | **40-80 MB** | 低 | ~0.3-0.5s | ★★★（Cairo 原生） | 低（复用全部脚本资产） |
| Python + GTK4 + cairo | 50-90 MB | 低 | 稍慢 | ★★（需关加速） | 低 |
| Rust + GTK4 | 130-170 MB | <0.5% | 快 | ★★（渲染内存大） | 高（数周） |
| Web（后端+浏览器） | 150-400 MB | 高 | 慢 | ★ | 中 |
| TUI（curses/btop 式） | 5-20 MB | <1% | 快 | ★★★ | 低但非 GUI |

**推荐：Python + GTK3（Cinnamon 原生主题、Cairo 渲染、Mint 自带依赖齐全）**
- 语言层差异极小（Python hello-world 6.6MB vs C 1.9MB）；真正的大头是渲染器，GTK3 天然规避
- 全部控制逻辑复用已验证脚本（m3.sh/三电源模式/battery-care），开发快、风险低
- 省电设计三原则：自适应采样（前台 1s/后台 5s/隐藏暂停）、控制按需执行、图形 Cairo 轻量绘制
- 备选：如用户偏好新 UI 风格可 GTK4 + GSK_RENDERER=cairo（主题需适配 Mint）
