## 一、总体结论

**当前配置总体科学合理，无错误配置。** 关键值均符合 Windows 对"高性能"方案的设计意图与社区最佳实践。
发现 **3 项可优化点**（电池续航向）与 **2 项用户偏好提示**，无一项属于"错误"。

### 2.5 实测佐证

- **SW Thermal Slowdown: Active** (nvidia-smi) — EPP=0 + Boost=Aggressive 使 AC 下整机贴近散热预算, MX150 与 CPU 共享热设计。**若想降低降频频率**: 将高性能方案 AC 的 EPP 从 0 调到 50-70 (控制台隐藏设置浏览器: 36687f9e-...-c6863, SUB_PROCESSOR), 峰值性能损失 <5%, 温度/降频显著改善。这是本机唯一值得考虑的"反直觉"优化, 属方案哲学选择而非纠错。

## 三、建议行动清单 (按价值排序)

| # | 行动 | 价值 | 风险 | 控制台操作路径 |
|---|---|---|---|---|
| 1 | DC Overlay → 平衡 | 低 (语义正确性) | 无 | 电源页 → 电源滑块 → 平衡 (需管理员) |
| 2 | 无线 DC → 功耗节省 | 中 (省 0.5-1W) | ping 略增 | 隐藏设置浏览器 → 搜 "wlansvc" 或 GUID 12bbebe6 → DC=1(低) / 0(中) |
| 3 | PCIe ASPM DC → 开 | 中 (省 0.3-0.8W) | 极少数设备兼容性 | 调优页 → 设备电源联动 → PCIe节能·电池 → 应用 |
| 4 | (可选) AC EPP 0→50-70 | 降温/减少降频 | 峰值性能 <5% 损失 | 隐藏设置浏览器 → 搜 "energy performance" → AC=50 |
| 5 | (偏好) DC 睡眠 30-60分 | 防深度放电 | 无 | 调优页 → 超时 |

**不建议动的**: EPP 拆分(Windows 管理)、Boost 拆分、最小状态、核心驻留、AHCI/NVMe、散热策略 —— 均已最优。

### 6.1 第二轮发现的重要纠正 ⚠️

**EPP 的完整 GUID 在本报告中写错了**：
- ❌ 报告此前引用: `36687f9e-3708-4174-b18a-4697475ae30c` (本机不存在此键)
- ✅ 本机真实 EPP: `36687f9e-e3a5-4dbf-b1dc-15eb381c6863`
- 另有两个变体 (Efficiency Class 1/2): 尾号 `...c6864` / `...c6865` (8250U 无 E-core, 不生效)
- 此前 powercfg 查询报"设置不存在"正是因为用了错误 GUID，并非设置缺失
- **数值本身 (AC=0/DC=84) 经注册表直读确证无误**

**Overlay 真实存储位置** (供控制台后续读写参考):
```
HKLM:\SYSTEM\CurrentControlSet\Control\Power\User\PowerSchemes
  ActiveOverlayAcPowerScheme = <overlay-guid>
  ActiveOverlayDcPowerScheme = <overlay-guid>
```

## 七、EPP A/B 受控实测 (2026-08-25)

> 方法: 自写负载脚本（4 线程 × 12s 计算突发 × 8 轮 + 30s 空闲采样，**非压力测试**），GPU 温度熔断阈值 80°C（实际最高 57°C，未触发）。
> 频率指标: `% Processor Performance`（×1.6GHz 基频 = 有效频率），WMI locale-proof 读取。EPP 写入经注册表回读验证，结束后自动恢复并复核。
> 数据: `C:\Users\<USER>\AppData\Local\Temp\opencode\epp_ab\data\{A,B}.csv`

| 指标 | A: EPP=0 | B: EPP=70 | 差异 |
|---|---|---|---|
| **空闲平均频率** | **186% ≈ 2.98 GHz** | **46.6% ≈ 0.75 GHz** | **空载时钟 -75%** |
| 负载平均频率 | 145.7% ≈ 2.33 GHz | 125.8% ≈ 2.01 GHz | **-13.7%** |
| 负载峰值频率 | 187% ≈ 3.0 GHz | 127% ≈ 2.03 GHz | -32% |
| GPU 最高温度 (同负载模式) | 57°C | 53°C | **-4°C** |
| GPU 结束温度 | 56°C | 53°C | -3°C |

### 7.1 实测裁决

1. **EPP 效应确证且强烈** —— 审计第 2.5/四节"可选优化 #4"从推断升级为实测结论。
2. **文献"<5% 峰值损失"过于乐观**: 持续多线程负载下实测吞吐约 -14%，峰值时钟 -32%。突发型/轻载场景差异感知接近零。
3. **意外发现（最有价值）**: EPP=0 使 CPU 在 28% 后台占用下仍维持 ~3.0GHz——高性能方案的空载功耗显著偏高；EPP=70 空载即降至 0.75GHz。**对续航的影响远大于负载端**。
4. **散热收益确证**: 同负载模式 GPU 低 4°C（CPU/GPU 共享热管，方向性代理指标），直接支持"降低 SW Power Cap 触发频率"的推断。

### 7.2 建议修订

- 若以续航/静音/降温优先: AC EPP 设 50-70 收益明确（尤其空载），代价为持续重载 -14% 吞吐
- 若以峰值性能优先: 维持 0（现状），已知代价是空载高时钟与更高热压力
- 折中值 40-50 未测，可作为后续实验（预期保留大部分空载收益、负载损失减半）
- 控制台实现建议: 在调优页将 EPP 暴露为一等滑块（当前仅藏在隐藏设置浏览器），支持 AC/DC 拆分
  → **已实现 (v6.5)**: 调优页 CPU 组新增"能效偏好 插电/电池"双滑块 + 应用按钮，进页自动回读当前值；test_suite TOTAL FAIL=0
