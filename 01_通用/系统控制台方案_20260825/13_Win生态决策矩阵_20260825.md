## 一、现状基线（全部实测确证）

### 固件/硬件层
| 事实 | 数值 | 对行动的含义 |
|---|---|---|
| 微码 | **0xE0** (prev=0x9E, 旧记录过时) | 对降压的影响未知 → 由 Step2 首档 -10mV 读回直接检验, 不需要任何前置 |
| 内存完整性 | HVCI=1, VBS=Running | 降压/PL 直控被闸的唯一软件原因, 开关可逆 |
| MX150 VBIOS | 功耗表损坏 (N/A, max=5001W) | GPU 功耗墙线永久关闭 |

### 系统层
活动方案 cb687381(高性能) · EPP 为隐藏设置(当前 AC=0/DC=84) · 电源设置 180 行 · EPP 等写入免管理员

### 已量化战果

## 三、执行序列（科学性: 信息先行 → 零风险 → 高收益带闸门）

```
Step 0  Win 侧信息采集 (半天, 只读)
   ├─ powercfg /a                    → S3 还是 Modern Standby? (定续航测量口径)
   ├─ DPTF 服务/驱动枚举             → 是否存在覆盖 EPP 的热策略? (定调优前提)
   ├─ powercfg /batteryreport + SRUM → 存档续航/能耗基线 (无基线则后续无法判定有效)
   └─ (可选) HWP Autonomous Window / Latency Sensitivity EPP 两组隐藏设置现状
        ↓ 结论写入 09A
Step 1  A1-A5 实现 + A5 实验 → 应用 B1 最优值 (约1天, 全部可逆)
        ↓
Step 2  B2 降压阶梯 (⚠️ 唯一需要你拍板: 关内存完整性的安全权衡)
   2a  关内核隔离 (设置→隐私和安全→设备安全性→内核隔离, 重启)
   2b  TS 写 -10mV → FIVR 窗口读回
       ├─ 读回一致 → 微码疑虑就地排除 → 逐档上探, 每档判据:
       │    读回一致 + 日常负载温度/频率前后对比 (铁律: 不做压力测试;
       │    任一档不稳即回退上一档定格; 历史 -105 死机红线已知)
       └─ 读回不变 → 记录现象; 可选加验 BIOS 关 VT (代价 Hyper-V/WSL2,
            默认不建议) 或终止本线
   2c  (通过后可选) B3: TPL 页设 PL1/PL2 目标值, 同法读回验证
        ↓
Step 3  B4 ACC 验证 + 监测复核 (LHM 降级链 / SW 降频计数 / Defender 状态)
```

## 四、测量协议

| 指标 | 工具 | 判据 |
|---|---|---|
| 降压生效 | TS FIVR 读回 + HWiNFO 交叉 | 读回=设定值 |
| 温度收益 | 控制台曲线均值, 同场景前后对照 | 复现 EPP 实验的 °C 级收益方法学 |
| 频率行为 | epp_ab.ps1 模板 (locale-proof 采样) | 单变量, 先后对照 |
| 续航 | batteryreport + 离电计时 (口径依 Step0) | 相对基线的差值 |

## 五、风险登记

| 风险 | 缓解 |
|---|---|
| 关 HVCI = 失去内核攻击面防护 | 开关可逆; 这是本方案唯一实质权衡, 收益是 B2/B3 全部 |
| 微码 0xE0 可能拒偏压 | Step2b 首档即暴露, 10 分钟出结论, 不带病深入 |
| Defender 标记 TS 内核驱动 | 发生则加排除或终止, 不对抗杀软 |
| 阶梯不稳定 | 逐档回退定格; -105 已知死机红线 |
