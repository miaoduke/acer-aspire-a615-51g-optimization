## 一、现有控制台能力盘点（截至 20260822 版）

**已实现（v1+v2 累计，24 项生态 + 11 项 v2 功能）**：
- 总览页：4 状态卡、CPU 每线程曲线（Cairo）、RAPL 多域功耗分解（内核 7.0 新能力）、限流原因徽章（G1）
- 场景页：6 场景卡 + AC/DC 自动切换状态 + 参数编辑（C1）+ GT 频率
- 电池页：协议采样健康度、充放电曲线、剩余时间估算（B2/B4）、历史 TSV 曲线（B1）、使用统计/循环计数/7 维科学分析
- 高级页：PL/Turbo/降压只读、GPU 模式切换、服务状态、kernel_guard 一键修复、thermal-guard 阈值（C2）
- 维护页 + 后台：性能日志 G3（30s TSV）、通知 H1（libnotify）、应用功耗排行 R1（cgroup 差分）、负载建议 P1

## 三、明确不做清单（延续并新增依据）

| 项 | 不做理由 |
|---|---|
| GTK4 迁移 | UHD620 上 GSK 加速渲染内存 2–3 倍；Mission Center/Resources 常态 130–170MB 即前车之鉴；GTK3+Cairo 40–80MB 达标 |
| Electron/Web 重栈（Netdata/Prometheus/Zabbix/Stacer 式） | 常驻 agent 违背省电原则；单机 YAGNI |
| 引入 TLP / auto-cpufreq / tlp-pd | 与自研 acdc-profile 栈 Conflicts= 冲突；我们已有更细粒度（PL/GT/PowerMizer/EPP）；PPD masked 是既定决策 |
| 风扇 EC 控制 / stress-ng / BD PROCHOT 写 / PSR2 | 死机史铁律（永久） |
| 主题系统 / per-app profile（CoreCtrl 式） | 单用户工具 YAGNI；场景机制已覆盖 90% 用例 |

## 四、技术选型结论（维持 + 微调）

| 层 | 选型 | 变化 |
|---|---|---|
| 语言/UI | Python 3 + GTK3 + Cairo | 不变（资源实测最优解） |
| 采集 | collector 直读 /proc+/sysfs，MSR 只读 rdmsr | 不变 |
| 控制 | sudoers 白名单脚本（场景管理/m3/prime-select/snapshot/adapt_test） | **白名单扩容 +2 条**（snapshot.sh、systemctl restart 三自有单元） |
| 数据 | TSV 落盘 + ring buffer + Cairo 曲线 | 不变，增加 7d 回看加载器 |
| 托盘 | GLib StatusNotifier/Cinnamon 托盘 API | 新增菜单动作 |
| 备选旁路 | Textual TUI（P3，SSH 场景） | 仅评估不承诺 |

## 五、风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| undervolt 值不一致导致观察期数据失真 | 高 | P0 立即核对；Phase 0 观察期内**只核对记录不改值** |
| 托盘菜单误触场景切换 | 中 | 二次确认对话框（仅对"写"类动作）；菜单项带当前场景高亮 |
| 服务重启按钮被滥用 | 中 | 仅暴露 3 个自有单元 + 操作后强制回读状态回显 |
| 快照中心误导"随时可拍"稀释回滚点 | 低 | UI 内嵌铁律文案：L1/L2 分级提示 + 低价值快照警示 |
| 观察期（C-state=4 验证）内开发引入变量 | 高 | **开发期功能全部为只读/UI 层，零系统写入**；涉及 gsettings 的 Night Light 推迟到 Phase 1 解锁后 |
