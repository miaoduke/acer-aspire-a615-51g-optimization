## 五、测试过程中发现的基础设施问题（非应用 bug，已记录）

1. **孤儿实例干扰**：第一轮套件 T7 异常路径未清理进程，遗留实例持有单实例互斥锁，导致第二轮所有启动落入"已在运行"提示框分支（内存 19MB 即消息框进程），数据全部失真。→ 套件增加开局强制清理；T4/T7 结果拆分为独立断言。
2. **CloseWindow API 不可靠**：user32 CloseWindow 虽返回 True 但未实际触发 FormClosing（SaveSettings 未执行）；改用 Process.CloseMainWindow()（同样投递 WM_CLOSE）后 T7 通过。应用侧保存逻辑本身无问题。
3. PowerShell 5.1 中静态 P/Invoke 必须以 `[Class]::Method` 调用，裸名被当作 cmdlet。

## 七、管理员模式 LHM 完整传感器验证（2026-08-23 追加）

### 7.1 遇到的问题与解决

| 问题 | 根因 | 解决方案 |
|---|---|---|
| LHM 始终显示"未启用" | `System.Memory` NuGet 包缺失（.NET Framework 4.8 不自带） | 通过 `nuget.exe install` 下载 LHM 0.9.6 及全部 14 个依赖包 |
| `BadImageFormatException` | NuGet net472 依赖 DLL 为 x86，但 exe 编译为 AnyCPU（64 位） | build.cmd 添加 `/platform:x86`，全部 DLL 统一 x86 架构 |
| `版本不匹配 HRESULT:0x80131040` | System.Memory 4.6.3 assembly version 为 4.0.2.0，LHM 编译时引用 4.0.5.0 | 创建 `SysConsoleDebug.exe.config` binding redirect 重定向到可用版本 |
| LHM 加载成功但传感器为 0 | `Computer.Hardware` 集合异步枚举，首次 `Open()` 后需等待 + 手动调用 `hardware.Update()` | InitLhm 增加 5 秒轮询等待 + CollectLhm 增加 `Update()` 调用 |
