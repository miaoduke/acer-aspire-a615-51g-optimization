## 二、操作系统两侧实况

### 2.1 Linux 侧（控制台目标系统）
- **发行版/桌面**：Linux Mint 22.3（Ubuntu 24.04 LTS 基座）+ Cinnamon 桌面
- **内核**：7.0.0-28-generic → 已升级 **7.0.0-29-generic**（HWE 式，acer-wmi-battery 自编译模块已随内核重编）
- **电源接管架构**：用户已决定由控制台完全接管电源管理——PPD 保持 masked；自研栈如下：

| 组件 | 作用 | 状态 |
|---|---|---|
| cpu-power-limit.service | PL1/PL2 功耗墙持久化（防 44W 突刺过热） | enabled，开机生效 |
| turbo-enable.service (turbo-guard.sh) | MSR 0x1A0 bit38 守护 + no_turbo 修复循环（30s） | running |
| intel-undervolt.service | undervolt 开机应用 | enabled ⚠ 配置值待核对：服务文件快照 -100mV vs 文档/实测 -49.8mV（见 04 方案 P0 核对项） |
| thermal-guard.service | 温度→PL 自动限流（56°C 触发 25→15W 并恢复） | 测试通过 |
| kernel_guard.sh | 内核变动检测 17 项 + 一键修复 | 已接入 GUI |
| acdc-profile.sh（v10） | AC/DC 场景自动切换（PL/EPP/GT 频率/PowerMizer） | 场景参数已 GUI 化 |
| snapshot.sh | Timeshift btrfs 快照封装（L1/L2 分级铁律） | CLI，待 GUI 化 |
| adapt_test.sh | 跨机适配测试向导（hardware_profile.json） | CLI |
| rasdaemon / smartd / journald 限容 | 硬件错误与日志治理 | 运行中 |

- **死机史铁律**（方案设计的硬约束）：①不碰 EC（fan_boost=死机4）②禁 stress-ng 满载（死机2/3）③MSR 只读不写 ④系统级修改前必须快照 ⑤更新后同步 WS1（留 3 份）⑥每阶段导出对话 md。
- **当前观察期**：C-state=4 待机闪屏验证窗口内（Phase 0，禁止叠加系统变量）——v3 开发期不得触发任何 MSR 写入/GRUB 变更。
- **数据资产**：data/perf_*.tsv、batt_*.tsv（30s 落盘）、charge_curve_*.tsv×3 天、knowledge 经验库（undervolt sweep/bench 对比/移植检查单）。

## 三、对方案设计的环境约束总结

1. **单机双系统 + 移动硬盘同步**：控制台的"备份/同步"功能有真实场景（WS1 铁律自动化已在脚本层实现）
2. **低压 U + 12GB + 已优化至 ~5.5W idle**：控制台自身必须保持 GTK3/Cairo 轻量栈（40-80MB），任何重渲染方案都会侵蚀优化成果
3. **死机史 + 观察期**：所有新功能默认"只读优先"，写操作全部走既有 sudoers 白名单 + 快照前置
4. **内核 7.0 新能力已吃到红利**（RAPL 多域分解已落地），后续内核升级依赖 kernel_guard 兜底
