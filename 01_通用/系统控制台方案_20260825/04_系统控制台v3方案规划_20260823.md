# 系统控制台 v3 方案规划
> 日期：2026-08-23
> 定位：在 v2（五页 GUI + 24 项生态 + 11 项改进）之上，补齐同行差距、把安全流程产品化、守住省电底线
> 前置约束：Phase 0 观察期（C-state=4 验证）内只做只读/UI 层开发；所有写操作走 sudoers 白名单；铁律全文见《未实现清单_20260820.md》第十节

---

## 一、版本目标（一句话）

**让"正确的操作流程"变成按钮**：托盘即达、服务可救、快照可拍、历史可回看——同时控制台自身保持 <80MB / 前台 CPU<0.5% / 后台近零。

## 二、架构增量（相对 v2）

```
console.py (GTK3 主循环, 自适应采样)
├── collector.py      [不变] 直读采集 + RAPL 多域 + 差分
├── controller.py     [扩容] 白名单 +2: snapshot.sh / systemctl restart {cpu-power-limit,turbo-enable,intel-undervolt}
├── ui_dashboard.py   [+回看入口]
├── ui_scenes.py      [不变]
├── ui_battery.py     [+7d 曲线加载器]
├── ui_advanced.py    [+服务操作按钮组]
├── ui_maintenance.py [+快照中心][+适配向导入口][+Night Light 开关(Phase1 解锁后)]
├── tray_menu.py      [新增] 托盘图标 + 6 场景直切菜单 + 当前场景高亮 + 写动作二次确认
└── history_view.py   [新增] TSV 加载 → 24h/7d 多指标叠加 Cairo 图（复用 Curve）
```

数据流与权限模型不变：GUI 无 root，全部特权经白名单脚本；采样前台 1s/失焦 5s/隐藏暂停。

## 四、资源预算与验收基线（延续 v1 标准）

| 指标 | 目标 | 测法 |
|---|---|---|
| 常态内存 | ≤80MB（含 7d 回看峰值 ≤110MB） | /proc/<pid>/status VmRSS |
| 启动时间 | <0.5s | time 到首帧 |
| 前台 CPU | <0.5%（i5-8250U） | top 采样 60s |
| 后台/托盘 | 近零（采样暂停或 ≥10s） | powertop wakeups 对比 |
| 回归 | v2 全部 11 项功能不回退 | console_full_test.py 全量通过 |

## 五、发布与同步流程（对齐既有铁律）

1. 每批完成 → `00_保存会话与日志.sh`（自动触发 sync_to_ws1.sh）
2. 本方案文件夹随更新换日期目录名（如 `系统控制台方案_20260824`），旧日期保留为历史
3. `export_session.py` 导出对话 md+图 → 会话记录/
4. 涉及服务的批次 → 先 `snapshot.sh create` 再动（L1 铁律）
