### 五-C、断电暴露的启动死锁修复 (20260826, T7 回归失败追查)
- **根因**: 断电后性能计数器表冷态, CollectPerProcGpu 首帧全量构造 335 个 PerformanceCounter **挂死**(非慢) → UI 线程死锁 → 窗口永不出现 → selftest/T7 连锁失败
- **修复**: PerProcGpu/PerProcDisk **后台化** (Sample 返回上次结果非阻塞, 重量级枚举丢线程池, Interlocked 防重入) → 断电后首次启动 8 秒可用
- 附带修复: DM_DISPLAYFREQUENCY 掩码误写 (0x800000=DM_ICMMETHOD → 0x400000); EnumDisplaySettings(null) 本机失败 → 显式主屏设备名
- 教训: 远程会话下判断物理屏必须 WmiMonitorID+Win32_VideoController 交叉, 不信 PrimaryScreen

### 五A、第三方工具调研结论 (20260825, 元审计修订后, 详见 11_文档)
- **EcoQoS**: 已调研 → 原生 API 可零依赖自实现 → 移入 📋代做#11
- **ThrottleStop**: 本机 HVCI=1/VBS=Running 是 Windows 侧降压+PL1PL2 失效的直接原因; 关内存完整性是必要条件但未必充分 (个别机型还需 BIOS 关虚拟化) → 用户决策项, 逐级实测 (-10mV 写读回验证起步)
- **Afterburner / XTU / NBFC / FanControl**: 全部有据❌ (MX150 官方不支持笔记本 / 8250U 被官方移除 / KB9022Q EC 探测失败 / 笔记本基本不支持)
- **5001W 异常已本地复现** (nvidia-smi: limit=N/A, 上限 5001W): VBIOS 功耗表未初始化, 非驱动损坏; GPU 功耗墙任何工具均无从下手
