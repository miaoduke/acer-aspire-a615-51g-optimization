## 四、结论

| 维度 | 评价 |
|---|---|
| **定位** | 单文件绿色"监控+电源管理+维护"三合一，主打笔记本电池场景（任务管理器/SI 均无） |
| **覆盖度** | 热门工具高频功能已覆盖 ~70%（监控类 85%，进程管理类 60%，调优类 30%） |
| **不可逾越项** | 内核级诊断(SI)、OSD(RTSS)、写硬件调优(AB) —— 与零依赖+只读铁律定位冲突，属**有意取舍** |
| **后续候选** | 进程树、每进程网络连接、历史回放 UI、计划任务管理（均为纯用户态 API，可无风险加入） |

### 5.2 新增"调优"页布局（第 3 个标签）

屏幕亮度滑块 → CPU 性能状态双滑块(插电/电池) → 超时四项(屏幕/睡眠 × AC/DC) → 设备联动四复选框(USB/PCIe × AC/DC) → GPU/显示只读信息区 → 底部状态栏(每次操作反馈)。

**设计原则**：所有写操作均为操作系统官方接口（powercfg/WMI），无 EC/MSR/驱动写入；进入页面自动读取当前值，应用后状态栏即时反馈成败。

## 六、v6.1 EC-WMI 硬件联动（2026-08-24 追加：用户解除 Windows 端 EC 写入限制）

> 用户决策：Windows 端暂不将 EC 写入列入铁律，允许安全范围内测试。
> 安全边界：仅经 Acer 官方固件 WMI 接口（非裸 EC 端口 I/O）、可逆（可恢复默认）、写入前后读校验。

### 6.1 接口探测（本机实测 11 轮）

| 项目 | 结果 |
|---|---|
| AcerGamingFunction 实例 | ✅ `ACPI\PNP0C14\APGe_0`, **Active=True** |
| 方法签名 | Get*: (gmInput UInt32 [in], gmOutput UInt64 [out])；Set*: (gmInput UInt64 [in], gmOutput UInt32 [out]) |
| 调用方式 | ManagementClass.GetInstances() + InvokeMethod（需管理员；非管理员实例枚举被拒） |
| GetGamingProfile(1/2/3) | ✅ 恒返回 2（读回不反映状态变化） |
| GetGamingFanBehavior/Speed(0) | ✅ =2/2（CPU 风扇, 2=自动）；风扇 1/2 = 0（不存在, 本机单风扇） |
| SetGamingProfile 返回码 | 写 2→rc=0 ✅；写 3→rc=0 ✅；写 1→rc=1 ❌拒绝；写 0→rc=2 ❌拒绝 |
| SetGamingProfile(3) 效果 | 固件接受但读回不变 → **实际效果本机无法远程验证** |
| SetGamingFanBehavior(manual) | rc=0 接受，但 SetGamingFanSpeed 读回不匹配 → 手动调速编码未验证，**不实现** |
| BatteryControl.GetBattInfoInterface(0,0) | uReturn=1，无 Set 充电限制方法 → **充电阈值不可用** |
| GetGamingSysInfo | ⚠️ 社区报告盲探参数可致死机（apge-control 项目警告），**禁止盲试** |

### 6.2 实现内容（调优页新增"Acer 硬件联动"组）

| 功能 | 状态 | 说明 |
|---|---|---|
| 性能配置切换 (安静/平衡/性能) | ✅ 实验性 | SetGamingProfile；固件接受 2/3、拒绝 0/1；标注"读回不变化, 效果以体验为准" |
| 风扇状态只读 | ✅ | 行为/速度 (2=自动) |
| 风扇手动调速 | ❌ | 编码未验证（写接受但读回不符），避免误写 |
| 电池充电阈值 | ❌ | 本机固件无此 WMI 方法 |

### 6.3 安全措施

1. 仅走 Acer 官方固件 WMI（ACPI\PNP0C14 APGe 设备），**非裸 EC 端口读写**
2. 全部操作可逆（写 2 即恢复平衡/默认）
3. 需管理员权限（UAC 明示）
4. UI 标注实验性与固件返回码，失败即显式报告
5. 未实现任何未验证编码的写入（风扇手动速度）
